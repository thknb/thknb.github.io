# Нұрсұлтан — портфолио сайты

## Қалай құрылған

GitHub Pages тек статикалық файлдарды көрсетеді — онда Python да, Django да, дерекқор да жұмыс істемейді. Сондықтан жұмыс былай бөлінген:

```
Сен: Django админкасында жоба не жазба қосасың      (өз компьютеріңде)
  ↓  python manage.py export_site
data/ ішіндегі файлдар жаңарады
  ↓  git push
Сайт жаңа жобаларды көрсетеді                        (GitHub Pages)
```

Дерекқор — сенің жұмыс құралың. Сайт оның нәтижесін ғана көрсетеді.

## Құрылым

```
portfolio/
├─ index.html          ← басты бет
├─ blog.html           ← жазбалар тізімі
├─ post.html           ← бір жазбаның беті
├─ css/style.css       ← дизайн
├─ js/main.js          ← басты беттің логикасы
├─ js/blog.js          ← блог беттерінің логикасы
├─ data/projects.js    ← АВТОМАТТЫ жасалады, қолмен түзетпе
├─ data/articles.js    ← АВТОМАТТЫ жасалады, қолмен түзетпе
├─ images/             ← суреттер
└─ backend/            ← Django + дерекқор
   ├─ contacts/        ← хабарламалар моделі
   ├─ projects/        ← жобалар моделі
   └─ blog/            ← жазбалар моделі + экспорт командасы
```

## 1. Бэкендті іске қосу (бір рет)

```bash
cd backend
python -m venv venv
source venv/bin/activate          # Windows: venv\Scripts\activate
pip install -r requirements.txt

python manage.py migrate          # дерекқорды жасайды
python manage.py createsuperuser  # ӨЗІҢЕ ЛОГИН-ПАРОЛЬ ЖАСАЙДЫ
python manage.py runserver
```

## 2. Дерекқорға кіру

**http://127.0.0.1:8000/admin/** — createsuperuser кезінде жасаған логин-парольмен кіресің.

Екі бөлім бар:

**Жобалар** — қосасың, өзгертесің, өшіресің. Әр жобада:
- Атауы мен сипаттамасы
- Күйі: жұмыс істеп тұр / аяқталды / жасалып жатыр
- Технологиялар — үтірмен бөліп жаз: `Python, Django, SQLite`
- Сурет файлы — `images/` ішіндегі файлдың аты, мысалы `project-1.jpg`
- Сілтеме — GitHub адресі
- Реті — кіші сан жоғары тұрады
- «Сайтта көрінсін» белгісін алып тастасаң, жоба сайтқа шықпайды


**Жазбалар** — блог мақалалары. Әр жазбада:
- Тақырып және қысқаша сипаттама
- Мәтін — Markdown форматында:
  - `## Тақырып` және `### Кіші тақырып`
  - `- тізім`
  - `**қалың**`, `*көлбеу*`, `` `код` ``
  - `[мәтін](сілтеме)` және `![сипаттама](images/сурет.jpg)`
  - `> дәйексөз`
  - ``` арасына код блогы
- Мұқаба суреті — `images/` ішіндегі файл аты
- Сілтеме (slug) — бос қалдырсаң тақырыптан автоматты жасалады
- Жарияланған күні

**Хабарламалар** — формадан келген хаттар (бэкенд серверде тұрғанда ғана толады).

## 3. Жобаларды сайтқа шығару

Админкада өзгерткен соң:

```bash
cd backend
python manage.py export_site
```

`data/projects.js` және `data/articles.js` файлдары жаңарады. Соларды GitHub-қа жүктесең болды.

## 4. Суреттерді қою

Суреттерді `images/` папкасына сал.

- **Өз суретің** — `images/photo.jpg`, сосын `index.html` ішіндегі `photo-placeholder.svg` жолын ауыстыр. Пропорция 4:5.
- **Жоба суреттері** — `images/` ішіне сал, файл атын админкадағы «Сурет файлы» өрісіне жаз. Пропорция 16:10. Бос қалдырсаң толтырғыш сурет тұрады.

## 6. Байланыс формасы

Қазір сервер жоқ, сондықтан форма толтырылған мәтінмен пошта қолданбаңды ашады. `js/main.js` басында:

```js
const API_URL = "";
const CONTACT_EMAIL = "nursultan@example.com";   ← өз поштаңды жаз
```

Кейін хабарламалар дерекқорға түссін десең, бэкендті Render-ге шығарасың (start command: `gunicorn config.wsgi`) және `API_URL`-ға сол адресті жазасың:

```js
const API_URL = "https://менің-сайтым.onrender.com/api/messages/";
```

Серверге шығарар алдында `backend/config/settings.py` ішінде міндетті түрде өзгерт: `SECRET_KEY` жаңа құпия мәнге, `DEBUG = False`, `ALLOWED_HOSTS` нақты доменіңе.
